Exception filters provide full control over the exceptions thrown across your application. DolphJS comes with a built-in exceptions layer which handles processing all unhandled exceptions. When an exception is not handled by your application code, it is caught by this layer, which then automatically sends an appropriate user-friendly response.

## Built-in Error Handler

By default, DolphJS catches any exceptions thrown within your routes, components, and controllers, formats them, and returns a standard JSON error response using its built-in `errorHandler` and `errorConverter`.

If you throw a standard Node `Error`, or one of DolphJS's built-in exceptions (like `DefaultException`, `BadRequestException`, etc.), the framework will automatically extract the status code and message.

```typescript
import { Get, Route, BadRequestException } from '@dolphjs/dolph';

@Route('/users')
export class UserController {
  @Get('/error')
  throwError() {
    // This is automatically caught by Dolph's built-in exception filter!
    throw new BadRequestException('Invalid user request');
  }
}
```

## Custom Global Exception Filter

While the built-in error handler is sufficient for many applications, you may want full control over the exceptions layer—for example, to add custom logging, integrate with third-party error trackers (like Sentry), or return a specific JSON schema to your clients.

DolphJS allows you to override the default error handler with a **Global Exception Filter**.

### Set the Global Exception Handler

Pass `onError` to `DolphFactory`. It receives every unhandled exception thrown while handling a request.

```typescript
import { DolphFactory, DRequest, DResponse, DNextFunc } from '@dolphjs/dolph';
import { AppComponent } from './app.component';

const dolph = new DolphFactory([AppComponent], {
  onError: (err: any, req: DRequest, res: DResponse, next: DNextFunc) => {
    console.error("Custom Error Tracker:", err.message);

    // Return a completely customized response structure
    return res.status(err.statusCode || 500).json({
      success: false,
      timestamp: new Date().toISOString(),
      path: req.url,
      error: err.message || 'Internal Server Error'
    });
  },
});

dolph.start();
```

`onError` runs first, giving you control over the final HTTP response. To fall back to Dolph's own handling, call `next(err)`.
