Shields are a powerful mechanism in DolphJS for applying middleware across an entire Controller. While standard middlewares (using `@UseMiddleware`) apply to single routes, Shields apply a layer of protection to _all_ routes defined within a controller class.

## Applying a Shield

To apply a shield, use the `@Shield()` class-level decorator. It accepts standard Express middleware functions.

A common use case is requiring authentication for every route in a controller.

```typescript
import { Route, Get, Shield, DRequest, DResponse, DNextFunc } from '@dolphjs/dolph';

// A basic Express middleware
const requireAuth = (req: DRequest, res: DResponse, next: DNextFunc) => {
    if (!req.headers.authorization) {
        return res.status(401).send('Unauthorized');
    }
    next();
};

@Shield(requireAuth)
@Route('admin')
export class AdminController {
    @Get('dashboard')
    async getDashboard() {
        // This route is protected by requireAuth
        return 'Welcome to the admin dashboard';
    }

    @Get('users')
    async getUsers() {
        // This route is ALSO protected by requireAuth
        return 'Admin Users List';
    }
}
```

## JWT Authentication

`jwtAuth()` is the built-in shield for JWTs. It verifies the token and puts its payload on `req.payload`, which `@DPayload()` reads.

```typescript
import { Route, Get, Shield, DPayload, jwtAuth } from '@dolphjs/dolph';

@Shield(jwtAuth(process.env.JWT_SECRET))
@Route('profile')
export class ProfileController {
    @Get()
    me(@DPayload() payload: IPayload) {
        return payload;
    }
}
```

| Use | Reads the token from |
|---|---|
| `jwtAuth(secret)` | The `authorization` header |
| `jwtAuth(publicKeyPath, { algorithm: 'RS256' })` | The `x-auth-token` header |
| `jwtAuth(secret, { cookie: true })` | The cookie set by `newAuthCookie()` |

To check permissions too, add `authorize`. Returning false answers `403`:

```typescript
jwtAuth(secret, { authorize: (payload) => payload.info?.role === 'admin' });
```

It works anywhere middleware does, so use `@UseMiddleware(jwtAuth(secret))` to protect one route.

## UnShielding Specific Routes

Sometimes you want an entire controller protected, except for one or two specific public routes (like a login endpoint). You can achieve this using the `@UnShield()` method-level decorator.

```typescript
import { Route, Get, Post, Shield, UnShield } from '@dolphjs/dolph';
import { requireAuth } from './auth.middleware';

@Shield(requireAuth)
@Route('auth')
export class AuthController {
    @Post('login')
    @UnShield() // Bypasses the requireAuth shield!
    async login() {
        return 'Public login route';
    }

    @Get('profile')
    async profile() {
        // Still protected by requireAuth
        return 'Private profile route';
    }
}
```

:::note
If you pass specific middlewares to `@UnShield(authMiddleware1, authMiddleware2)`, it will only bypass those, leaving any other shields active. Pass the same function reference you gave to `@Shield`. A function that's built again won't match, even with identical code: for `@Shield(requireRole('admin'))`, store the result in a variable and use that in both places. If nothing matches, the route stays protected and a warning is logged at startup.
:::
