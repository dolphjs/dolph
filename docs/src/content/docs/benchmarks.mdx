## Three engines, one codebase

DolphJS 3.1 ships three HTTP engines. The same application — same controllers, same DTO validation, same envelope — ran on each of them through `adapter: express`, `adapter: fastify` and the new `adapter: dolph`, DolphJS's own engine. Higher throughput and lower latency are better; lower memory is better.

### How these three were measured

- One app, one route table: [`benchmark/servers/dolph.ts`](https://github.com/dolphjs/dolph/blob/dev/benchmark/servers/dolph.ts), run three times with `DOLPH_ADAPTER` set to each engine.
- `autocannon`, 100 connections, keep-alive, no pipelining, **one 15-second round per path**, production mode, Node 22.
- Memory is the server process's resident set size, sampled every 250 ms: *idle* after warm-up and before load, *peak* across every path.
- Load generator and servers on the same laptop, as with the table above — compare engines with each other, not against absolute numbers.
- Zero errors on every path for all three engines.

Reproduce it with:

```bash
git clone https://github.com/dolphjs/dolph
cd dolph && npm install
node benchmark/runner.js --only dolph,dolph-express,dolph-fastify
```

## Method

- 100 connections with `autocannon`, keep-alive on and no pipelining.
- Every path gets a warm-up, then 7 rounds of 5 seconds each.
- Each round runs every path once, and every other round runs them in reverse, so a slow moment on the machine or a run order doesn't favour one path.
- The result is the median round.
- Node 22 in production mode, on one laptop, with the load generator on the same machine.

Because of that last point, compare the paths with each other and don't read these as absolute speeds. In this run, the gap between Dolph and Express moved by about 5% either way from round to round. A difference of a percent or two is too close to call, so read it as being about level.

Express and Dolph don't send identical responses. Dolph wraps what you return in its standard envelope, so its responses are slightly larger.

## Run it yourself

```bash

```
