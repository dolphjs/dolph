Handlebars (`hbs`) is a popular logic-less templating engine. DolphJS integrates smoothly with Handlebars for robust Server-Side Rendering.

## Installation

Install the Handlebars engine for your adapter. On Express:

```bash
pnpm install express-handlebars
```

On Fastify, install `handlebars` along with `@fastify/view` and `@fastify/static`.

## Configuring Views

Set the view engine in `dolph_config.yaml`.

```yaml
# dolph_config.yaml
views:
  engine: handlebars
  dir: views
  assets: public
```

`dir` holds your templates, and `assets` is served as static files. Both are relative to the project root.

## Creating the View

Create a `views` directory in your project root, and add an `index.handlebars` file.

```html
<!-- views/index.handlebars -->
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>{{title}}</title>
</head>
<body>
    <h1>{{heading}}</h1>
    <ul>
        {{#each users}}
            <li>{{name}}</li>
        {{/each}}
    </ul>
</body>
</html>
```

## Rendering the View in a Controller

The controller logic remains entirely agnostic of the view engine. The `@Render()` decorator handles the handover.

```typescript
// src/page/page.controller.ts
import { Route, Get, Render } from '@dolphjs/dolph';

@Route('pages')
export class PageController {


  @Get('home')
  @Render('index') // Corresponds to views/index.hbs
  async getHomePage() {
    // Data passed directly to Handlebars
    return {
      title: 'DolphJS Handlebars App',
      heading: 'Welcome to SSR with Handlebars',
      users: [
        { name: 'Eve' },
        { name: 'Frank' }
      ]
    };
  }
}
```

:::tip
Because DolphJS normalizes the rendering pipeline with `@Render()`, you can switch between EJS, Pug, or Handlebars by merely updating the `MVCAdapter` and your view files, without ever touching your Controller logic!
:::
