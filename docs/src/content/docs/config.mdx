DolphJS uses a central configuration file named `dolph_config.yaml`. This file sits at the root of your project and dictates how the `DolphFactory` initializes the server, databases, and middleware.

## Basic Configuration

A standard `dolph_config.yaml` looks like this:

```yaml
database:
  mongo:
    url: mongodb://localhost:27017/dolph_db
    options:
      useNewUrlParser: true
      useUnifiedTopology: true
  typeorm:
    options:
      type: postgres
      host: localhost
      port: 5432
      username: root
      password: password
      database: dolph_db
      synchronize: true
      entities:
        - "src/models/*.ts"
```

## Environment Variables

DolphJS automatically merges your `.env` files with your configuration. You can reference environment variables within your application using standard `process.env` properties, or you can rely on the factory to inject these values directly.

## Configuration Sections

### Server

These keys sit at the top level of the file.

- **port**: The port your application will listen on. Overrides the `PORT` environment variable. Defaults to `3030`.
- **env**: The running environment (e.g., `development`, `production`). See [Environment and error details](#environment-and-error-details).
- **jsonLimit**: The maximum JSON body size. Defaults to `5mb`.
- **adapter**: The HTTP server to run on, `express` or `fastify`. Defaults to `express`. See [Fastify](/techniques/fastify).

#### Environment and error details

DolphJS runs in production mode unless you ask for development. It uses development mode only when `NODE_ENV` or `env` is `development` and neither is set to anything else.

| `NODE_ENV` | `env` in config | Mode |
|---|---|---|
| not set | not set | `production` |
| `development` | not set or `development` | `development` |
| not set | `development` | `development` |
| `production` | `development` | `production` |
| `development` | `production` | `production` |

Stack traces and the messages of unexpected errors are only sent to clients in development mode. Set `NODE_ENV=development` on your machine to see them.

### Database

DolphJS provides out-of-the-box auto-initialization for **MongoDB** and **TypeORM**. Install only the driver you use:

```bash
npm install mongoose
npm install typeorm
```

If a driver is configured but not installed, the app stops at startup and says which package to install.

:::tip
When you define the `mongo` or `typeorm` keys, `dolph.start()` connects to them before the app takes traffic, and stops the app if one fails. Set `required: false` on a database to start without it.
:::

**Strictly Typed Configuration:**
Under the hood, the `dolph_config.yaml` values map directly to the official configuration interfaces provided by the underlying ORMs. For TypeORM, the `options` block maps perfectly to `DataSourceOptions`. This ensures full auto-completion and seamless support for advanced database configurations right out of the box!

**Retrieving Database Instances:**
Once auto-initialized, you can instantly grab your database clients anywhere in your application:

```typescript
import { getDataSource } from '@dolphjs/dolph';

// Retrieve TypeORM DataSource
const dataSource = getDataSource();
const userRepo = dataSource.getRepository(User);
```

:::note
**Sensitive Credentials:** When initializing a database, if the value `"sensitive"` is passed to specific fields in your `dolph_config.yaml`, the framework automatically checks your `.env` file for corresponding keys to use instead. This keeps your credentials securely out of source control.
- **MongoDB**: Passing `"sensitive"` to `url` pulls from `MONGO_URL`.
- **TypeORM**: Passing `"sensitive"` to `username`, `password`, `host`, or `url` pulls from `SQL_USER`, `SQL_PASSWORD`, `SQL_HOST`, and `SQL_URL` respectively.
:::

### Middlewares

DolphJS bundles commonly used Express middlewares. You can turn them on in your config:

- **cors**: Configures Cross-Origin Resource Sharing. Set `activate: true` to turn it on, and `origin` to the site or list of sites allowed to call your API. Without an `origin`, no cross-origin requests are allowed and a warning is logged at startup. Use `origin: '*'` to allow every site.
- **helmet**: Secures your Express apps by setting various HTTP headers. Set it to `true` for the defaults, or to an object of [helmet options](https://helmetjs.github.io/):

```yaml
middlewares:
  helmet:
    contentSecurityPolicy: false
```

JSON and URL-encoded body parsing are always on.

### Routing

Controls how routes are mounted.

- **base**: A path prefix added to every route, such as `/v1`.

## Accessing Configuration in Code

While `dolph_config.yaml` drives the framework's bootstrap phase, you can also access configuration values dynamically in your components using standard environment variables if you have mapped them.

```typescript
import { DolphFactory } from '@dolphjs/dolph';
import { AppComponent } from './app.component';

const dolph = new DolphFactory([AppComponent]);

dolph.start();
```
