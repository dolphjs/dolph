Handling file uploads in DolphJS is extremely straightforward because the framework ships with its own robust, internal file uploading utility `useFileUploader` provided by `@dolphjs/packages`. You don't need to manually install `multer` or any external dependencies!

For images, use [`imageUpload()`](/techniques/image-upload) instead. It adds dimension limits and removes metadata such as GPS location.

## Creating the Middleware

You can configure `useFileUploader` with storage destinations, file filters, and extension restrictions. DolphJS provides both `diskStorage` and `memoryStorage` helpers to manage where your files go.

```typescript
// src/utils/uploader.config.ts
import { useFileUploader, diskStorage } from '@dolphjs/dolph';
import path from 'path';

// Configure storage
const storage = diskStorage({
  destination: (req, file, cb) => {
    // Save files to the 'uploads' directory
    cb(null, './uploads');
  },
  filename: (req, file, cb) => {
    // Prevent naming collisions
    const uniqueSuffix = Date.now() + '-' + Math.round(Math.random() * 1e9);
    cb(null, file.fieldname + '-' + uniqueSuffix + path.extname(file.originalname));
  },
});

export const uploadMedia = useFileUploader({
  storage,
  fieldname: 'document',
  type: 'single', // can also be 'array' or 'fields'
  limit: 5 * 1024 * 1024, // 5MB limit
  extensions: ['.png', '.jpg', '.jpeg', '.pdf'] // automatically filters files!
});
```

Requests are rejected rather than silently trimmed:

- A file type that isn't allowed returns `415`.
- A file whose contents don't match its extension returns `415`. A `.png` has to really be a PNG. Types with no signature, like `.txt`, are checked by name only. Set `verifyContent: false` to turn this off.
- More than `maxFields` text fields, 100 by default, returns `400`.
- A file on an unexpected field, or beyond `maxCount`, returns `400`.
- `.html`, `.xml` and `.xhtml` aren't allowed by default, because serving them back could run scripts in a visitor's browser. Add them to `extensions` if you need them.
- Files sent as a browser `Blob` arrive named `blob`, so they're checked by their declared type.
- An upload that takes longer than `timeout` (30 seconds by default) returns `408`, and anything already written to disk for that request is removed.

## Applying to Controllers

Use the `@UseMiddleware` decorator to apply the newly created `uploadMedia` middleware to your route. When the request reaches your handler, the file data will be securely populated in `req.file` (or `req.files` if uploading an array).

```typescript
// src/upload/upload.controller.ts
import { Route, Post, DReq, UseMiddleware, BadRequestException, DRequest } from '@dolphjs/dolph';
import { uploadMedia } from '../utils/uploader.config';

@Route('files')
export class UploadController {

  @Post('single')
  @UseMiddleware(uploadMedia)
  async uploadSingleFile(@DReq() req: DRequest) {
    if (!req.file) {
      throw new BadRequestException('No file uploaded or invalid format');
    }

    // Pass file data to a service, or return the path
    return {
      message: 'File uploaded successfully',
      filePath: req.file.path,
    };
  }
}
```

:::caution
Make sure the `uploads` directory exists at the root of your project. Otherwise, the upload stream will fail with an ENOENT error when attempting to write to disk.
:::
